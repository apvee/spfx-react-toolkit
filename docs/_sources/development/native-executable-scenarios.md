# Native executable scenarios

Native Property Pane examples use a private sample protocol to keep source-owned configuration separate from the initialized WebPart's SDK lifecycle. They require actual native Edit and Close, native resource mappings, the matching initialized host, and its existing authentication and delegated permissions.

## Connected native host

The sample connects one terminal native adapter per initialized WebPart. Select an owning native example, prepare while the pane is closed, then use this WebPart's actual native Edit and Close. Unprepared or closed getters return generic Show title and description settings with preparation and recovery instructions. The selected source owns native business configuration; navigation and Reset do not replace a produced session.

[PropertyPaneSitePicker](../../api/property-pane/pickers.md#propertypanesitepicker) includes the complete integrated metadata/file cascade in addition to its minimal Site case and ordinary integration recipes. The integrated case preserves parent-dependent arrays, independent file settings, saved JSON and an explicit read-only compatibility inspection. That inspection compares saved legacy preferences, including false and empty settings, with the effective focused/extended native menu policy after an actual getter supplies a live SDK reader. It never restores legacy switches or performs picker I/O.

The existing scenario diagnostics include explicit Inspect native host lifecycle and Clear native host observations commands. Each instance retains at most 64 scalar observations: ordinal, event, public open flag and optional stable field key. Inspect snapshots genuine getter, child render, parent Rendered, latest field disposal and Complete observations into DOM-visible JSON; it grants no native ownership or recovery acknowledgement. Dedicated Source/Compiled fixtures remain local evidence. Actual Workbench timing and authenticated selection require separate validation.

## Author a bounded native source

Use a unique local title, a named synchronous `Demo`, and literal `host: 'webPart'`, `kind: 'read'`, `contentPlacement: 'configuration'`, `hostAdapter: 'propertyPane'` and a useful `observe` sentence. Follow the [executable authoring contract](documentation.md#executable-example-authoring) for optional render regions and `resetRevision`. The first observed revision, including a nonzero value, is not Reset.

Declare the source-local structural `DemoPropertyPanePort<SourceProperties>` and its environment/controller/result types using public peers only, as in the complete pilot. The optional port exposes only `prepare(create)`. The environment supplies `instance: BaseClientSideWebPart<P>`, live `readProperties: () => P` and bounded `refresh: () => void`. Controller function properties are `getConfiguration`, `fieldChanged(path, oldValue, newValue)`, `configurationComplete`, `changesApplied` and `dispose`. Preparation returns either a prepared lease with idempotent `release`, or a blocked reason. There is no source open/close API. These are private tooling types, not new public library exports.

Use the exact host property domain, including optionality and mutable arrays. The Site pilot owns only optional `pickerSites?: SitePickerValue[]` and stable native key `picker-sites`. Canonical validation checks the complete optional port, strict function-valued members and unsafe source types without reading private app files. Separately, emitted app glue proves every source key/domain against the concrete WebPart properties before common loader erasure; extra host properties are allowed. Structural port assignability alone is insufficient for narrower array domains. Do not import app types, the adapter, generated modules or compiled library outputs into canonical source.

Preparation only records a factory and token while the global pane is closed and latest owned native DOM is empty. It never constructs business controllers/fields, opens, closes, refreshes or queries. The actual permitted getter constructs the controller transactionally and reads the live SDK bag on every configuration request. Source factory/configuration exceptions retain the prior owner without publishing a partial candidate. Keep the controller module-local and independent of Demo setters/reset closures. For explicit saved-value inspection, the transient factory may give the Demo a live `readProperties` function; clear that local reader on Reset/departure and clear the factory after production. The controller must retain only its host environment.

Every initial configuration has one page and a first genuine factory subject in exactly `{ isGroupNameHidden: true, groupFields: [actualSubject] }`, with absent `groupName` and `isCollapsed`. Do not introduce a sentinel, duplicate field or fabricated render callback. This public group composition ignores persisted named collapse state in the pinned SDK. The real child render witness precedes native parent Rendered; later collapse of a separate named group retains the committed business owner.

## Reset, ownership and disposal

Reset preserves Demo identity, invalidates original source commands, cancels only its own unproduced lease and clears local observations. A produced native session survives explorer Reset/navigation until its actual native lifecycle ends. Reset is not native Discard, persistence rollback or a server undo. The SDK alone updates/replaces/applies properties; never restore a captured property bag. Explicit saved-value inspection reads the live SDK bag, not a provider snapshot.

Keep the candidate factory, latest produced configuration, last witnessed native view and latest mounted descriptor per DOM distinct. Native Complete while open, Apply/inactivity, foreign switch and delayed Start do not establish Close. Latest native disposal cleans up once even while the public open flag is still true; stale descriptor disposal cannot unmount its same-key replacement. Withdrawn hidden cold descriptors can witness a retained business view without mounting/querying. They cannot resurrect a retired cell. Refresh is permitted only during synchronous fieldChanged dispatch for this instance's current native business view, never from Start/Complete/background work or foreign scope.

The private adapter retains at most two business controllers, including transient successor construction, under the supported route below. Warm committed owners retire on a new genuine child/parent commit or actual Close with closed flag and empty latest-owned DOM. Cold supersession retains the latest produced owner until a fully constructed successor replaces it under the successful SDK DTO/install premise. Issued wrappers retain small mutable cells; retirement clears original callbacks, controller/environment references and factories. A dispose call alone is not closure-release evidence. This is reference-clearing evidence, not a heap/GC claim.

## Supported route and external failure boundary

The bounded route is the pinned SPFx 1.21.1 default reactive controller with React 17 legacy synchronous commits: plain finite configuration/property data, one cached resource Promise per instance, shared component loading, successful nonreentrant SDK DTO/install processing, no spinner delay, debounce, asynchronous native validator or multipage override. Component completion reads the mutable latest DTO. A real earlier native commit means those component chunks are warm; do not invent a later cold chunk after that commit.

Source construction errors are caught before publication. External SDK, React or host errors **after** the source getter returns have a different boundary: reload before further native scenario work. Supported hooks cannot reliably detect/attribute that failure or enforce automatic recovery. For a cold B installed while chunks wait, both successful C install and a post-getter C DTO exception can expose identical adapter callbacks, closed flag and empty DOM; the actual installed DTO differs. A later component completion may still read B in the failed path. Tests keep this counterexample visible; no timeout, fake acknowledgement, global listener, private SDK hook or recovery pass resolves it.

Local fixtures establish bounded protocol/source/compiled behavior only. Actual Workbench native Edit/Close, getter/open flag, commit/disposal order, cold close/reopen and two-instance switching remain separate authenticated validation. Nonreactive Apply/Discard, content-panel/iframe routes and all manifest hosts are not established by this pilot. Do not perform tenant mutations or grant permissions as setup.
